# Deploy Meew Decor from GitHub to Vercel

Updated 14 October 2026.

## Import and publish the storefront

1. Extract `meew-decor-source.zip`. Put the contents of the `meew-decor` folder into a GitHub repository, including `package.json`, `package-lock.json`, `vercel.json`, `.env.example` and the hidden configuration files. Do not upload the ZIP itself or `node_modules`.
2. In Vercel, choose **Add New → Project → Import Git Repository** and select that repository.
3. Set **Root Directory** to the directory containing `package.json` (leave it at the repository root if you followed step 1). The framework is **Next.js**. Keep the output directory at its framework default.
4. Choose **Deploy**. The committed `vercel.json` selects `npm run build:vercel`; the package pins Node 24. No Cloudflare account, D1 binding or build-time secret is needed for the storefront.

The first deployment supports the collection, product details, search, filters, saved pieces, shopping bag and Messenger enquiry flow. It does not accept payment until the commercial configuration below is complete. GitHub pushes trigger subsequent deployments through Vercel's Git integration.

## Enable persistent store management

Vercel uses a remote **Turso/libSQL** database. Cloudflare/Sites uses **D1**. Their data is separate: existing D1 orders or settings are not automatically copied to Turso. Choose one live selling deployment to avoid splitting orders and inventory. Never use a local file or `/tmp` for production orders on Vercel.

Create a Turso database and database access token using your own account. Add these to Vercel **Project → Settings → Environment Variables**:

| Variable | Value |
| --- | --- |
| `TURSO_DATABASE_URL` | Database URL, starting with `libsql://` or `https://` |
| `TURSO_AUTH_TOKEN` | Database access token; secret |
| `STORE_ADMIN_EMAIL` | The actual store owner's email |
| `STORE_ADMIN_PASSWORD_HASH` | Generated by the password helper below; secret |
| `STORE_SESSION_SECRET` | Generated by the password helper below; secret |
| `COMMERCE_ENABLED` | `false` until payment acceptance is complete |
| `SITE_PUBLIC_URL` | Canonical public HTTPS origin, without a path, such as your Vercel production domain or custom domain |

Use separate credentials and databases for Preview and Production. Never connect untrusted pull-request deployments to the live order database. None of these secrets should have a `NEXT_PUBLIC_` prefix.

From the extracted project, with Node 24:

```sh
npm ci
npm run admin:password
```

The helper asks for a password of at least 16 characters without showing it, then prints a salted password hash and a random session secret. Paste their **raw values** into the Vercel environment-variable UI. Keep the values private; the helper does not save them. Do not put the password itself in Vercel or GitHub.

Next, create an ignored local `.env.local` file with **only** `TURSO_DATABASE_URL` and `TURSO_AUTH_TOKEN` for the intended database, then apply its schema:

```sh
npm run db:migrate:vercel
```

This is an explicit database operation, not part of `next build`. It applies committed migrations in order, records checksums, and safely skips already-applied migrations. It refuses changed historical migrations. Verify that you chose the intended database before running it. The file is ignored by Git; remove local secrets when no longer needed.

Redeploy in Vercel after setting environment variables. Open `/admin`, sign in with the configured email and password, and enter the real prices, stock, delivery rates and policies. Sessions expire after eight hours. Logout clears the current browser session; rotating the password hash or session secret invalidates all existing sessions.

## Activate bKash

Set `BKASH_ENV`, `BKASH_API_VERSION`, `BKASH_USERNAME`, `BKASH_PASSWORD`, `BKASH_APP_KEY` and `BKASH_APP_SECRET` securely. Follow [BKASH_INTEGRATION.md](./BKASH_INTEGRATION.md). The existing adapter requires merchant confirmation for Tokenized Checkout **v1.2.0-beta**; v2 is not implemented. No real merchant payment has been tested.

The callback endpoint is `/api/payment/callback` on `SITE_PUBLIC_URL`. Vercel deployment protection, a password wall, or a private preview must not block the approved public storefront/callback. Complete sandbox and merchant-approved live acceptance before setting `COMMERCE_ENABLED=true` and enabling checkout in `/admin`. Real product prices, quantities and policies are still required from Meew Decor.

## Local development and checks

```sh
npm ci
npm run dev:vercel
npm test
npm run typecheck
npm run build:vercel
npm run start:vercel
```

The Node app uses `@libsql/client/web` over HTTPS; no database connection occurs during build. Without database/owner variables, browsing works and the owner page shows setup guidance.

For local owner testing, Next.js expands `$` inside `.env.local` values. Escape each dollar sign in `STORE_ADMIN_PASSWORD_HASH` as `\$` there. In Vercel's UI, use the unescaped hash. Use localhost or local HTTPS for the Secure owner session cookie; an arbitrary HTTP LAN address cannot retain it.

`npm run dev`, `npm run build` and `npm start` retain the Cloudflare/Sites workflow. The `@meew/platform` alias chooses Node/Turso in Next and Cloudflare/D1 in Vite. The authentication choice is made by the build, never by incoming identity headers. Cloudflare retains its ChatGPT owner sign-in.

Run the two targets' builds sequentially: both frameworks generate route types in `.next/types`. `npm run typecheck` regenerates Next route types before checking, so switching from a Cloudflare build to Vercel does not leave conflicting generated types.

## Verification and limits

The Vercel target is a real Next.js production build with static storefront pages and dynamic API routes. Automated tests cover database transaction rollback, migration history, stock/payment rules, signed sessions, login throttling and spoofed identity rejection. The build and local server are verified; no Vercel account deployment or remote Turso acceptance is claimed by these checks.

Vercel setup references: [Next.js hosting](https://vercel.com/docs/frameworks/full-stack/nextjs), [build settings](https://vercel.com/docs/builds/configure-a-build), [environment variables](https://vercel.com/docs/environment-variables). Database reference: [libSQL client](https://tursodatabase.github.io/libsql-client-ts/).
